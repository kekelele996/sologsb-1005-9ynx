# 专利权利要求映射工作台

用于专利代理人与审查人员核对权利要求、技术特征和说明书支持依据的前端工作台。所内统一维护技术特征表，代理人在各自案件工作区维护权利要求正文、特征层级与说明书依据，数据按浏览器本地保存，可恢复上次工作位置。

## 功能

- 多案件工作区：代理人各自维护权利要求、技术特征、说明书段落与批注。
- 所内技术特征表：统一条目（编号、名称、定义、分类、版本），支持“改定义 / 拆分为多条 / 停用”三类暂存变更，一次发布。
- 发布后按案件自动对应（`src/app/reconcile.ts`）：
  - 旧条目被拆分/停用：在后继条目中按 Sørensen–Dice 相似度仲裁，**唯一命中自动换引用**；
  - 旧条目改定义：按新定义重新核对，吻合的自动升级到新版本，差异过大的**挂起等代理人确认**；
  - 候选为空、最高分不达标或前两名分差过小（不唯一）时一律挂起，**说明书依据、正文保留在本案件特征上**，不会落到已不存在的条目；
  - 挂起项可在特征编辑器中人工确认：改指其他特征表条目，或转为本案件自定义特征。
- 失败隔离与按案件重试：发布同步逐案件事务化，某案件处理失败时仅该案件回滚到处理前，其他案件与特征表保持发布结果；重试只重新处理仍挂起/引用失效的特征，已对上的不再重复动。特征表页提供“故障演练”开关模拟单案件中断。
- 旧工作台数据升级：本地 v1 单案件数据在启动时自动迁移为“引用特征表”的 v2 多案件结构（相同“名称+定义”合并为同一特征表条目），再参与对应。
- 录入独立/从属权利要求与说明书段落；为特征设置父级层级、特征间引用和负责角色，映射一个或多个说明书支持段落。
- 自动提示引用循环、缺少依据、空特征、挂起对应、失效特征表引用和“特征已删除但映射未清理”。
- 角色切换与批注隔离：代理人可维护主数据与特征表，审查员只能修改本人批注，观察者只读。
- 全量操作撤销重做，使用 `Ctrl/⌘ + Z` 与 `Ctrl/⌘ + Shift + Z`。
- 保存权利要求版本，逐项比较正文差异并恢复历史版本（恢复后会再按当前特征表核对一遍）。
- 导出完整 JSON 或可核对的 CSV（含特征表引用列），本地保存滚动位置。

## 技术栈

- Angular 19、TypeScript、RxJS
- PrimeNG 19、PrimeIcons
- 浏览器 `localStorage`（v2：`patent-claim-mapping-workbench-v2`，自动接管旧 v1 键）

## 本地开发

```bash
npm install
npm start
```

开发服务器监听容器内端口 4200，仅用于本地开发；项目不在源码中定义宿主端口。

## 测试与构建

```bash
npm test     # node:test 纯函数/服务级测试（对应引擎、按案件回滚与重试、v1 迁移）
npm run build
```

产物位于 `dist/patent-claim-workbench/browser`。

## Docker

```bash
docker build -t sologsb-1005 .
docker run --rm -p 10005:80 sologsb-1005
```

nginx 在容器 80 端口提供构建产物，并按根端口表映射到宿主 `10005`。

## 数据说明

数据与版本存在浏览器本地。若需团队共享或长期归档，请在后续接入后端存储；当前实现为明确的前端离线原型。
