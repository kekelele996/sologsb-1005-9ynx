# 专利权利要求映射工作台

用于专利代理人与审查人员核对权利要求、技术特征和说明书支持依据的前端工作台。所内统一维护一份**技术特征表**，各案件在自己的工作区补写权利要求正文、特征层级与说明书依据，并按特征表的新定义自动对齐。数据按案件本地保存，可恢复上次工作位置。

## 功能

- **所级技术特征表**：统一维护特征编号、名称与标准定义，按 revision 发布；支持新增、改掉定义（旧定义退役、唯一生效）、拆成多条（旧条目退役、保留血缘）。
- **多案件工作区**：代理人各自在案件内录入独立/从属权利要求、说明书段落，拆分技术特征、设置父级层级与特征间引用；案件特征通过 `tableFeatureId` 引用特征表条目，也可脱离特征表保留为案件本地特征。
- **按新定义重新对上**：特征表发布后，案件同步时逐条评估引用旧条目的特征——
  - 能与唯一生效/替代定义唯一对应（相似度达标且领先）的引用**自动换**到新条目，并记录自动换日志；
  - 一拆多条且无法唯一对应、或旧条目无替代的引用**挂起**，在“挂起确认”页列出候选与匹配度，等代理人改挂或确认脱离；
  - 说明书依据、层级、批注始终挂在案件本地特征上，特征删除或版本恢复时同步清理挂起，不让依据落到案件中已不存在的特征上。
- **失败隔离与按案件重试**：同步按案件逐个处理，单个案件失败即整体回退到处理前，特征表与其他案件照常生效；重试只重新评估仍未对上的引用，已自动换好的部分不重复处理。
- **旧数据升级**：工作台里已有的 v1 单案件数据（特征不引用特征表）在载入时先升级为引用特征表的结构——按特征正文与表定义匹配挂接，再按当前特征表走一遍自动换/挂起，然后才参与对应。
- 自动提示引用循环、缺少依据、空特征、挂起引用和“特征已删除但映射未清理”。
- 角色切换与批注隔离：代理人、审查员只能修改本人批注，观察者只读。
- 全量操作撤销重做，使用 `Ctrl/⌘ + Z` 与 `Ctrl/⌘ + Shift + Z`。
- 保存权利要求版本，逐项比较正文差异并恢复历史版本。
- 导出完整 JSON 或可核对的 CSV（含特征表条目与对齐版本），本地保存上次案件、视图、标签页和滚动位置。

## 技术栈

- Angular 19、TypeScript、RxJS
- PrimeNG 19、PrimeIcons
- 浏览器 `localStorage`

## 本地开发

```bash
npm install
npm start
```

开发服务器监听容器内端口 4200，仅用于本地开发；项目不在源码中定义宿主端口。

## 生产构建

```bash
npm install
npm run build
```

产物位于 `dist/patent-claim-workbench/browser`。

## Docker

```bash
docker build -t sologsb-1005 .
docker run --rm -p 10005:80 sologsb-1005
```

nginx 在容器 80 端口提供构建产物，并按根端口表映射到宿主 `10005`。

## 数据说明

- 存储键：`patent-claim-mapping-workbench-v2`（旧版 `...-v1` 数据会在首次载入时自动迁移为多案件 + 特征表引用结构）。
- 特征表与全部案件都保存在浏览器本地；侧边栏“载入旧版数据并升级”可演示 v1 数据迁移，“恢复出厂演示数据”可重置内置示例。
- 演示场景：案件甲停留在特征表 r1（B 被拆、D 被改定义），点“全部对齐”可看到 D 自动换为 D1、B 挂起；勾选案件上的“演练：下一次处理失败”可验证按案件回退与重试。
- 若需团队共享或长期归档，请在后续接入后端存储；当前实现为明确的前端离线原型。
